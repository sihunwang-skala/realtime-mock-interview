## 설계
- 같은 지문, 같은 합성 답변 5개(정상 3, "모름" 2)를 실시간으로 재생하고 [답변 끝] 순간부터 첫 소리까지를 잰다 (런타임이 내는 LATENCY 이벤트).
- 조건마다 하나만 바꾼다. 조건 사이 60초 쉰다. 시작 전에 부하를 확인한다(부하 4 이상이면 대기).
- 열 지표: Whisper가 일한 횟수·시간(재현됨). CPU초는 Ollama 모델 프로세스 재시작과 다른 세션 때문에 같은 설정에서도 134초 / 5.5초 / 128초로 흔들려 **버렸다**.
- 채택 규칙: 속도 후보 = 중앙값 8% 이상 AND 0.05초 이상 감소. 열 후보 = Whisper 시간 15% 이상 감소 AND 중앙값이 0.05초 넘게 늘지 않음.

## 채택한 변경
- `runtime.py` VoiceRuntime 기본값 `partial_every` 2.0 → 4.0 (한 줄). 창(`partial_window` 14초)은 그대로.
- 효과: 말하는 동안 Whisper 부분 받아쓰기 호출이 절반. 응답 속도는 같음.
- 부작용(확인 필요): 끼어들기 검사가 4초마다라서 반응이 최대 2초 더 늦어질 수 있음. 이번 시험은 응답 시간만 쟀고 끼어들기 반응은 안 쟀다.

## 이번 실험이 보여준 더 큰 문제 (미해결)
- 5번째 시도(정상 답변)만 느렸다: 기준 ③ 4.03초, 채택 조건 2.58초.
- 시도별 분해: 질문 생성 1.3~1.8초 + 음성 첫 조각 0.8~1.4초. 다른 시도는 둘 다 0초(미리 만든 꼬리질문 + 미리 만든 음성을 씀).
- 즉 **미리 만든 꼬리질문이 없을 때 생성 경로가 2초를 넘긴다.** 실제 실험에서 2초를 넘긴 DEEPEN 3건(5.2~5.5초)과 같은 패턴이다.
- 이 값이 조건에 따라 0.5초씩 흔들려서(생성 1.81 vs 1.33초, 음성 1.36 vs 0.78초) 이번 5개 시도로는 조건 간 비교가 안 된다.

## 꼬리질문 구조 변경 (2026-11-20, 시험 20회씩, 합성 답변)
- 정의: 꼬리질문 = 방금 한 말을 짚어 더 파고드는 질문 (되풀이 아님). 자료: Rubin & Rubin 계열 방법론 자료, Koji/QuestionPro 문서(횟수 1~3, 표준 없음).
- 바뀐 것: ① 질문 직후 꼬리질문 후보 미리 만들기(5/5, 약 1.5초) ② 질문 3개 보충이 우선(남은 질문 0~1개) ③ 보충 질문은 지금까지 한 모든 질문과 겹치지 않게 ④ 꼬리질문을 같은 주제어 겹침만으로 버리지 않음 ⑤ 답변의 새 단어 → 그 단어가 나온 지문 문장 → 그 문장만 근거로 질문(근거 없으면 질문 안 만듦) ⑥ 꼬리질문 연쇄 최대 3번.
- 결과: 답변 기반 꼬리질문 통과 10/10회 중 1회(수정 전) → 20회 중 8~9회(40~45%, 두 번 잼). 질문 쓰기 중앙값 1.2초 → 0.8초. 통과 못 하면 미리 만든 후보 또는 다음 준비된 질문으로 넘어감.
- 아직: 근거·검증·순서·불분명 확인 유형은 시험 데이터에 조건이 없어 미시험(구현은 더 자세히/근거/검증만). 연쇄 3번과 질문 3개 보충 우선순위는 라이브에서 확인 전. 서버 재시작 필요.
- 유형 순서(확정): 더 자세히(새 단어가 든 내 문장이 짧을 때) → 검증 → 근거 → 순서 묻기. 시험 지문 9문장 중 조건에 맞는 문장: 근거 1, 검증 4, 순서 1 → 근거·순서는 지문이 그런 문장을 가질 때만 나옴.
- 순서 묻기 구현(`seq_gap`, LLM 호출 없는 틀): 지문 문장을 연결어미로 3단계 이상 나눌 수 있을 때, 답변이 중간 단계를 건너뛰면 "'B'도 설명해 주시겠어요?", 마지막 전에 멈추면 "그다음 단계는 무엇인가요?". 단계의 희귀 단어가 답변에 하나도 없을 때만 빠졌다고 봄. 작은 예문 5개로만 확인(실제 지문 미확인). 서버 재시작 후 적용.

## 끼어들기 수치 (근거 없음 → 실험으로 조정)
- 3초 / 8초 / 질문 단어 겹침 20% / 반복 30% / 75초는 모두 시작값이며 논문 근거는 못 찾음. 말하기 속도(서울말 자연발화 초당 약 4~5음절, KoreaScience 2018·2017)만 확인.
- "질문과 무관한 말"의 글자 수 90 → 60으로 변경. 이유: 검사 창이 14초라 보통 속도에서 약 75~93자뿐이라 90자는 사실상 도달 불가. (끼어들기 이후 누적 글 전체를 쓰는 안은 받아쓰기 부담 때문에 보류, 14초 창 유지)
- 다음: 10쌍 시험의 오탐/유도 적중으로 각 값을 비교 조정. 정상 답변 길이 분포로 75초 재검토. 중간 과정 숫자 오탐은 '총·전체·최종' 앞뒤 숫자만 보는 안 보류.

## 세 번째 실제 세션(JUKJAE 위키 지문) 점검과 수정
- 질문 품질: 맥락 없는 지시어로 시작하는 질문("이 섹션에서…", "이 별명을…", "이 핑크색…", "이제 다른…")·영상 제목 찌꺼기(♬ ㅣ × SBS)·지문에 없는 근거를 묻는 질문("…돌파하는 데 어떤 전략", "…이유"인데 문장에 이유 없음)이 나옴 → `bad_question`에서 이/그/저로 시작하는 질문 전부 제외, 제목 찌꺼기 제외, `grounded`(질문의 내용 단어가 원문 문장에 있어야 하고, '이유'는 문장에 이유 표현, '전략/방법/방식/절차/목적/효과'는 문장에 같은 단어가 있어야 함)로 질문 은행 후보를 검사.
- 정답 "정재원"이 '틀림': 첫 질문의 기준 지문이 위키 인포박스·분류 덩어리여서 판정 모델이 쓰레기를 보고 판정. `head_of`가 문장 단위(산문)만 쓰도록 변경.
- 화면: 실험 끝 요약과 저장된 실험 상세에서 꼬리질문은 파란색 "🔗 AI 꼬리질문 n/3 (유형)", 끼어들기는 빨간색, 새 영역 질문은 "➡ AI 새 영역 질문". 이 세션은 판정이 전부 '틀림/모름'이라 꼬리질문이 한 번도 없었음(새 영역 질문이 전부 "꼬리질문"으로 표시돼 혼동). "2초마다 갱신" 문구를 4초로 수정.
