채택: 3개씩, 1개 남으면 보충. 한 라운드(1.8초)가 질문 하나 소비 시간(35초)보다 훨씬 짧아 보충이 끊길 일이 거의 없다 (3초 안에 질문을 연속 건너뛰면 예외, 그땐 즉석 생성 경로를 탐). 문장은 지문 전체를 건너뛰며 고름(황금비 간격) → 한 라운드가 넓은 범위를 덮음.
질문 품질 (14개 샘플): 대부분 지문 개념을 직접 묻지만 "이 앞부분에서…", "전문가의 의견을 구해 주실 수 있나요?"처럼 지문과 어긋나는 질문이 14개 중 2~3개 있음. 별도 과제.

## 질문 품질 규칙 (2026-11-20, 사용자 지적 3건)
지적: (1) 한 질문에 두 가지를 묻는다 ("차이점과 자율성 단계에서 역할 구분을 이해하고 있나요?") (2) "재현성(재현성)"처럼 괄호 안에 같은 말을 반복 (3) 비슷한 질문이 다시 나온다 ("Agentic AI와 workflow 차이"가 두 번).
조치
- 한 가지만 묻기: 프롬프트에 규칙 추가 + 걸러내기(planner.one_thing): 75자 초과, 예 아니오 확인형("이해하고 있나요?"), 접속(와/과/및/그리고/또한) 2개 이상, 요청 2개 이상, 물음표 2개 이상이면 버림.
- 괄호: 같은 말 반복 괄호는 한 번만 남기고, 나머지 괄호는 소리 내어 읽기 어색하므로 표시만 제거 (자율성 단계(L0~L5) → 자율성 단계 L0~L5).
- 비슷한 질문: 이미 한 질문과 핵심어가 60% 이상 겹치면 같은 질문으로 보고 버림 (전에는 75%). 질문 목록 만들 때도 같은 기준 적용.
검사 (사용자가 지적한 문장 포함 7문장): 지적된 두 가지 묶음 질문은 걸러지고, 한 가지 질문 5개는 통과. 질문 목록 샘플 12개에서 두 주제 묶음 질문이 눈에 띄게 줄었으나 "위험한 작업의 위험을 어떻게 평가하고 관리합니까?"처럼 '평가하고 관리'를 묶는 경우는 일부 남음 (미해결).
한계: 걸러내기는 형태 규칙이라 의미 중복은 놓칠 수 있고, 반대로 정상 질문을 버릴 수 있다 (핵심어 60% 기준).

## 답변 평가가 다음 질문을 늦추지 않게 (2026-11-20, 사용자 요구: 절대 늦추면 안 됨)
관찰: "난 몰라요." 답변 뒤 받아쓰기 1.95초, 총 2.42초 (보통 받아쓰기 0.4~0.8초). 평가(LLM 채점)와 질문 목록 보충이 같은 모델과 CPU를 쓰고 있어 겹쳤을 가능성이 있음 (확정 못 함, 원인 미확인).
조치
- 평가는 AI가 다음 질문을 말하는 동안(사용자가 조용하고 마이크가 꺼진 구간)에만 돌린다.
- 사용자가 말을 시작하거나 답변을 끝내면 평가를 즉시 중단한다 (테스트: 1초 걸리는 작업이 사용자 발화 0.3초에 시작하면 0.31초에 중단, 답변 종료 0.2초에 시작하면 0.21초에 중단).
- 중단된 평가는 결과 상세를 열 때 만들어 저장한다 (모범 답안과 같은 요청). 그래서 실시간 화면에 평가가 안 보이는 답변이 생길 수 있다.
- 질문 목록 보충도 사용자가 말하는 중에는 시작하지 않는다.
미확인: 실제 세션에서 받아쓰기 시간이 정상(0.4~0.8초)으로 돌아오는지. 확인하려면 같은 조건으로 10쌍 실험 후 받아쓰기 시간 분포를 비교해야 함.

## 마이크 대기 여부와 질문 보충 버그 (2026-11-20)
- 확인(코드 읽기): "시작"은 지문 전송(즉시 응답, 질문 만들기는 서버 백그라운드) 후 마이크를 열고 서버에 연결한다. 마이크는 질문 만들기를 기다리지 않는다. AI가 말하는 동안 마이크 입력을 받지 않는 것은 에코 방지용 설계다.
- 버그: 질문 보충(3개 이하 남으면 다음 3개)이 실제로 안 돌았다. 테스트(질문 건너뛰기 6번): 질문 3개 그대로. 원인: 보충 확인이 음성 미리 만들기 루프 안에 있었고, 그 루프는 20여 문장(문장당 약 1.3초) 음성을 다 만든 뒤에야 다음 검사를 함.
- 수정: 보충을 독립 루프로 분리(0.3초마다 확인). 은행이 새로 만든 질문을 센 뒤에 판단해 같은 보충이 반복되지 않게 함(sync_bank 호출). 세션 종료 시 루프 취소.
- 미확인: 수정 후 같은 건너뛰기 테스트에서 질문 수가 3, 6, 9로 늘어나는지 (열 때문에 실행 보류).

### 보충 확인 결과 (2026-11-20, 최적 방식으로 재확인)
1차 (독립 루프만 적용): 질문이 3 → 6에서 멈춤. 원인: 옛 질문 미리 만들기(engine._prefetch)가 질문 은행과 별개로 대기 줄을 4개까지 채워서 은행 보충 조건(남은 질문 1개 이하)이 성립하지 않았음. 이 옛 경로는 지문 부분 JSON 호출(400토큰)을 돌리고 "한 가지만 묻기"와 괄호 정리를 거치지 않아 열과 두 가지 묶음 질문, 중복 질문의 원인이기도 했음.
수정: 지문(질문 은행)을 쓸 때는 옛 미리 만들기를 끔 (지문 없는 기본 RFP 질문 모드는 그대로).
2차 결과 (질문 건너뛰기 9번, 7초 간격, 약 10문장 지문): 질문 수 3 → 6(건너뛰기 1) → 9(4) → 10(7) → 더 만들 문장 없음 표시(8). 보충 오류 0건.
의미: 남은 질문이 1개 이하가 되는 시점마다 3개씩 보충되고, 지문의 쓸 만한 문장이 바닥나면 멈춘다. 테스트 지문이 짧아(문장 약 10개) 10개에서 끝났음.
미확인: 실제 음성 세션에서의 받아쓰기 지연과 열 변화.

### 받아쓰기 지연과 LLM 동시 실행 (측정, 2026-11-20)
방법: data/audio의 녹음 6개(5~26초, 합성 음성 샘플)를 faster-whisper small(mps)로 받아쓰기. 조용할 때, LLM(질문 은행 보충)이 동시에 돌 때, 다시 조용할 때 비교.
| 조건 | 평균 | 최대 |
|---|---|---|
| 조용할 때 | 0.53초 | 0.95초 |
| LLM 동시 실행 | 1.05초 | 1.91초 |
| 다시 조용할 때 | 0.53초 | 0.94초 |
결론: LLM이 같이 돌면 받아쓰기가 약 2배 느려진다. 실험에서 본 받아쓰기 1.95초는 이 최대값과 같아서, 그때 LLM 작업(평가, 보충, 꼬리질문 작성)이 겹쳤을 가능성이 높다 (직접 확인은 못 함).
조치: (1) 평가는 AI 발화 중에만 돌고 사용자가 말하면 중단, (2) 보충은 사용자 발화 중 시작하지 않고 답변이 끝나면 즉시 중단, (3) 답변이 끝날 때 아직 쓰는 중인 꼬리질문은 취소해 LLM을 비움.
미확인: 실제 사람 목소리 세션에서 받아쓰기가 조용할 때 수준(0.4~0.8초)으로 돌아오는지.

## 평가와 모범 답안은 리포트를 열 때만 (2026-11-20, 사용자 결정)
- 세션 중 LLM 작업 제거: 질문마다 모범 답안 쓰기(start_answer), 답변 채점(_late_verdict), 질문 은행의 모범 답안과 꼬리질문 후보, 옛 질문 미리 만들기(_prefetch)를 모두 끔. 남은 LLM 작업은 질문 은행 보충(3개씩, 사용자 발화 중 시작 안 함)과 답변 도중 꼬리질문 작성뿐.
- 리포트 열 때: 답변마다 LLM 1번(평가 + 이유 + 모범 답안을 한 번에, 실패하면 2번). 측정: 답변 하나당 1.5~2.4초, 결과는 실행 파일에 저장해 다시 열면 0초.

- 실시간 평가 표시는 제거 (사용자: 실제 모의 면접에서는 끝난 뒤에 본다).
- 공유용 요약: 내 실험 결과의 상세 아래 "공유용 요약"에서 보기/복사. 같은 내용이 data/live_runs/<id>.summary.md 파일로 저장됨(설정, 한눈에 보기, 턴별 시간, 2초 초과 턴과 그때 다른 작업, 질문과 답변, 평가와 모범 답안).

## 질문의 출처 문장을 기억해 두기 (2026-11-20, 사용자 제안)
- 질문을 만들 때 어느 지문 문장에서 나왔는지(위치 번호와 문장 원문 300자 이내)를 질문과 함께 저장하고, 꼬리질문은 부모 질문의 출처를 물려받는다. 세션은 답변마다 그 출처(ref_text)를 실험 파일에 남긴다. 리포트에서 채점할 때는 이 출처만 LLM에 넣고, 옛 실행 파일에만 키워드 검색으로 대신한다. 지문 전체를 넣지 않는다 (입력은 질문 + 답변 + 출처 문장 약 100~400자).
- 측정 (답변 6개, phi4-mini, 한 번에 하나): 출처 기억 방식 총 10.1초(평균 1.68초, 최대 2.02초), 키워드 검색 방식 총 9.3초(평균 1.55초, 최대 1.96초). 속도 차이 없음(순서에 따른 모델 예열 차이 가능). 시간은 입력 길이가 아니라 평가와 모범 답안을 쓰는 출력(약 100~150 토큰)이 좌우한다.
- 이점은 속도가 아니라 정확도: 키워드 검색은 엉뚱한 문장을 참고로 잡아 정상 답변이 "틀림"으로 채점된 사례가 있었음. 출처 기억은 질문이 나온 바로 그 문장을 쓴다.
- 리포트 여는 시간: 답변 10개 기준 약 15~17초, 한 번만(이후 저장본 0초). 세션 중에는 0초.
