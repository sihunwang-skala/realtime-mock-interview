# 테스트 기록 규격 (모든 테스트가 같은 항목을 남긴다)

각 테스트는 `results/mini_<id>.record.json`(공개 가능, 저장소에 포함)에 아래 항목을 남긴다.
실제 녹음에서 나온 텍스트가 들어가는 상세 사례는 **`results/mini_<id>_REAL_local.json`**(로컬 전용, git 제외)에만 둔다.

| 구역 | 항목 | 왜 남기나 |
|---|---|---|
| A 식별 | test_id, 제목, 실행 시각, git 커밋, 실행 명령 | 나중에 같은 조건으로 재현 |
| B 목적 | 무엇을 알아내려는 테스트인가, 가설 | 결과를 읽는 기준 |
| C 방법 | 단계별 절차, 지표 정의(예: CER 계산식, "응답 지연 = 실제 발화 끝 → AI 첫 소리 송출"), 판정 기준 | 숫자 의미 오해 방지 |
| D 데이터 | 샘플 ID 3개, 길이(초), 종류(실제 사람 / 합성), 기준 텍스트의 출처, 데이터 취급(로컬 전용 / 클라우드 허용) | 공정성, 프라이버시 |
| E 구성 | 모델과 버전, 장치(mps/cpu), 파라미터(silence_ms, confirm_ms, 전략, 정책), 콜드/웜 | 비교 조건 |
| F 환경 | 하드웨어, OS, 실행 중 다른 작업 유무, 네트워크 | 지연 해석 |
| G 시간 | **테스트 전체 소요 초**(모델 로드 포함), 처리한 오디오 초, 실시간 대비 배율 | "몇 초 만에 했나" |
| H 결과 | 샘플별 원시값 + 집계(평균, P50/P95 등 의미 있을 때만) | 분석 |
| I 사례 | 성공 1개 + 실패/이상 1개 (입력, 출력, 왜 그런지). 합성은 원문, 실제는 로컬 파일에만 | 숫자만으로 안 보이는 것 |
| J 이상 징후 | 발견한 버그, 누수, 오류 (예: 내부 라벨이 질문에 섞임) | 개선 목록 |
| K 한계 | 표본 수, 합성 여부, 같은 모델이 만들고 채점한 편향, 기준 텍스트의 한계 | 과대 해석 방지 |
| L 재현 | 정확한 명령, 필요한 파일, 환경변수 | 재실행 |
| M 상태 | IMPLEMENTED_AND_VERIFIED / FAILED / BLOCKED / NOT_TESTED 와 사유 | 정직한 표기 |
