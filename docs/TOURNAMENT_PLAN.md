# 토너먼트 실험 계획 (한 번에 하나만 바꾸고, 2개씩만 살아남기)

## 원칙
- **한 축만 바꾸고 나머지는 현재 최선으로 고정**한 뒤 점수를 매기고, **상위 2개만** 다음으로 올린다.
- 사용자는 **`답변 끝` 버튼**으로 답변을 끝낸다. 테스트에서는 실제 발화 끝 시점에 버튼이 눌렸다고 가정한다(수동 턴 모드).
- 합성 음성으로만 클라우드(심사, 음성 인식)를 쓴다. 실제 녹음은 로컬에서만 처리한다.

## 순위 규칙
| 축 | 순위 기준 |
|---|---|
| STT | 받아쓰기 틀린 비율(CER) 낮은 순, 같으면 빠른 순 |
| 질문 전략 / LLM | "쓸 만한 비율"(첫 소리 2초 이내 **이면서** 꼬리질문 품질 3.5/5 이상) 높은 순 → 품질 → 속도 |
| 끼어들기 정책 | 정답 라벨이 있는 시나리오에서 F1, 같으면 잘못 끼어든 횟수 적은 순 |
| TTS | 첫 소리까지 빠른 순 |

## 단계
**1단계 — 로컬 모델 1개(qwen2.5:7b)로 고정하고 나머지 축 토너먼트** (14번 실행)
1. STT: base / small / turbo / gpt-transcribe(클라우드) → 2개
2. 질문 전략: direct / hybrid / precomputed / two_track → 2개
3. 끼어들기 정책: rule / llm / hybrid / off → 2개
4. TTS: AVSpeech / say → 2개(둘 다)

**2단계 — 1단계 최선 구성으로 고정하고 LLM 토너먼트** (13번 실행, 큰 모델 4개 제외)
- 내장 Ollama 5개: qwen2.5:7b, qwen3:8b, qwen3.5:4b, llama3.1:8b, llama3.2:3b
- 외장하드 Ollama 7개: exaone3.5:7.8b, exaone-deep:7.8b, qwen3.5:9b, gemma4:12b, ministral-3:14b, aya-expanse:8b, phi4-mini:3.8b
- **제외(이 컴퓨터에서 무리):** gemma4:26b, qwen3.6:27b, qwen3.6:35b(메모리 32GB에서 느리고 발열), gpt-oss:20b(추론형, 13GB, 불러오다 시간 초과)
- 로컬 모델 사이에 **90초씩 쉬면서** 진행(발열 완화)
- 클라우드 1개(별도 레인): **gpt-6-luna**(가성비 최고, 공식 가격 기준)
- 로컬 상위 2개 + 클라우드 1개가 결승으로

**3단계 — 결승**
- 로컬 레인: STT 2 × 전략 2 × 끼어들기 2 × TTS 2 × LLM 2 = **32개**
- 클라우드 레인(gpt-6-luna 고정): STT 2 × 전략 2 × 끼어들기 2 × TTS 2 = **16개**
- **최종 조합 48개**, 마지막에 실제 사람 목소리 클립으로 검증

## 알려진 제약
- Hugging Face 다운로드가 느리다(초당 50~300KB). A.X 14.5GB는 10시간 이상 걸릴 수 있어 백그라운드로 두고 기다리지 않는다.
- 내장 디스크 여유가 4.7GB뿐이라 새 모델은 모두 외장하드에 둔다.
- 각 시험의 표본은 3개이므로 순위는 경향이다. 결승에서 실제 사람 클립으로 한 번 더 확인한다.
